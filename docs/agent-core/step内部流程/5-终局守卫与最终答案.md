## 💡 设计要点

1. **"纯文本"是候选而非结论**：六道守卫任何一道未满足，"最终答案"会被打回循环（注入 user 块 continue）——假完成在 WebBrain 是一等公民的防御对象。
2. **恢复有界**：每类恢复 nudge 恰好一次（Phase 3 的标志重置保证"真进展后重新获得机会"），二次失败产出**透明**的终止文案而非静默 `done`。
3. **步数耗尽也有答案**：`_buildStepLimitSummary`（L3516）从消息里合成"为什么停"的摘要——用户看到原因而不是空 `done` 事件，Continue 按钮可用。
4. **错误路径与 finally 分离**：外层 catch 记 trace 并 rethrow（让 `processMessage` 的 finally 做状态恢复），内层 finally 恒 `_endTraceRun`——trace 生命周期不漏。
